3.3.1 Phương pháp Kiểm thử
================================================================================

Hệ thống được kiểm thử theo ba mức độ:

1. Unit Testing:
   Kiểm thử các hàm và module riêng lẻ (Feature Engineering, XGBoost model,
   RLS logic). Đảm bảo mỗi component hoạt động đúng theo thiết kế.

   Framework: Pytest (Python backend), Jest (JavaScript frontend)

2. Integration Testing:
   Kiểm thử tương tác giữa Frontend và Backend. Ví dụ:
   - Người dùng đăng nhập → nhận JWT → gọi API → dữ liệu được lọc theo RLS
   - Upload CSV → parse → validate schema → bulk load → kiểm tra số dòng
   - Dashboard load → request song song → tất cả biểu đồ render

3. End-to-End (E2E) Testing:
   Kiểm thử toàn bộ quy trình: đăng nhập → điều hướng → tương tác → export.
   Lý tưởng dùng Cypress hoặc Selenium nhưng thực hiện bằng manual testing
   cho bản demo.

4. Performance Testing:
   Kiểm tra: thời gian response API, thời gian load page, memory usage,
   CPU usage, DB query time.

5. Security Testing:
   Kiểm tra: xác thực JWT, RBAC enforcement, SQL injection prevention,
   CORS configuration, Data encryption.

3.3.4 Kết quả Kiểm thử Bảo mật
================================================================================

✓ JWT Authentication:
  - Token HS256 được sinh chính xác, chứa payload đầy đủ
  - Expiration handling: 24 giờ, trigger refresh khi hết hạn
  - Password hashing: SHA256 + salt, verify bằng hmac.compare_digest()

✓ RBAC (Role-Based Access Control):
  - 4 vai trò (admin, executive, regional_manager, store_manager)
  - Kiểm tra quyền strict: chỉ admin mới create user, upload CSV
  - HTTP 403 Forbidden khi user không đủ quyền

✓ RLS (Row-Level Security):
  - Regional Manager chỉ xem dữ liệu khu vực mình
  - Store Manager chỉ xem cửa hàng mình quản lý
  - Lọc áp dụng ở tầng API (Backend) không phải Frontend
  - Data không bị leak qua API response

✓ CORS Configuration:
  - Whitelist origin: http://localhost:3000, https://vercel_domain
  - allow_credentials=True khi whitelist cụ thể (không dùng *)
  - allow_methods, allow_headers rõ ràng

✓ SQL Injection Prevention:
  - SQLAlchemy ORM với parameterized queries
  - CSV: sanitize column names (remove special characters)
  - User input validation qua Pydantic models

✓ Data Encryption:
  - HTTPS recommended (khi deploy Production)
  - Sensitive data (token, password) không hard-code
  - Environment variables cho API keys

3.3.9 Vấn đề Phát hiện và Giải Pháp
================================================================================

Vấn đề 1: Cold Start (Sản phẩm mới)
─────────────────────────────────────────────────────────────────────────────
Triệu chứng: Dự báo sai lệch lớn cho sản phẩm mới (< 30 ngày lịch sử)
Nguyên nhân: Không đủ dữ liệu lịch sử để học lag features
Giải pháp: Sử dụng Global Model thay vì model riêng mỗi sản phẩm
Kết quả: Giảm sai số ~50% cho sản phẩm mới (MAPE 15% → 8%)

Vấn đề 2: High Cardinality (Số sản phẩm lớn)
─────────────────────────────────────────────────────────────────────────────
Triệu chứng: Training time quá lâu, memory overflow
Nguyên nhân: 500+ sản phẩm × 22 features × 190K rows = 2GB DataFrame
Giải pháp: Chunking (xử lý 50 sản phẩm một lần) + gc.collect()
Kết quả: Training time < 2 phút, memory capped at 300MB

Vấn đề 3: Outliers (Giá trị bất thường)
─────────────────────────────────────────────────────────────────────────────
Triệu chứng: Dự báo confidence bounds quá rộng
Nguyên nhân: Khuyến mãi đột ngột, thiên tai, dịch bệnh tạo spike/dip
Giải pháp: XGBoost robust to outliers (tree-based, không linear). Thêm
           logic trim outliers nếu cần.
Kết quả: Interval width vẫn hợp lý (50-80 units)

Vấn đề 4: Data Freshness (Độ tươi dữ liệu)
─────────────────────────────────────────────────────────────────────────────
Triệu chứng: Dashboard hiển thị dữ liệu cũ (chập chờn)
Nguyên nhân: ETL chạy mỗi 30 phút, realtime ingest chưa implement
Giải pháp: Background thread chạy ETL mỗi 5 phút + SSE streaming realtime
Kết quả: Data lag < 5 phút (acceptable cho retail operations)
