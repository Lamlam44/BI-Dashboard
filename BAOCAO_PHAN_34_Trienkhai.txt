3.4.2 Triển khai Frontend (Vercel)
================================================================================

--- Chuẩn bị Triển khai ---

1. Cài đặt Vercel CLI:
   npm install -g vercel

2. Tạo file vercel.json cấu hình:
   ```json
   {
     "buildCommand": "npm run build",
     "outputDirectory": ".next",
     "framework": "next.js",
     "nodeVersion": "18.x"
   }
   ```

3. Tạo .env.production:
   NEXT_PUBLIC_API_BASE_URL=https://api.yourdomain.com
   (Backend API URL - sẽ cập nhật sau khi deploy backend)

--- Quy trình Triển khai ---

1. Login vào Vercel:
   vercel login

2. Deploy ứng dụng:
   vercel --prod

3. Vercel tự động:
   - Detect Next.js framework
   - Chạy npm run build
   - Minify + optmize bundle
   - Deploy tới global CDN
   - Assign domain: your-app.vercel.app (hoặc custom domain)

--- Kết quả Triển khai ---

✓ Domain: https://bi-dashboard-green.vercel.app/
✓ SSL/TLS certificate: Tự động
✓ CDN Edge Locations: 250+ locations globally
✓ Build time: ~2-3 phút
✓ Deployment time: < 30 giây
✓ Environment variables: Manage qua Vercel Dashboard

--- Tối ưu hóa Vercel ---

1. Incremental Static Regeneration (ISR):
   Các trang được pre-build lúc build time, revalidate mỗi 600 giây.
   Giảm load server, tăng tốc độ phản hồi.

2. Image Optimization:
   Next.js Image component tự động compress, resize theo device.
   Giảm bandwidth 50-70%.

3. Code Splitting:
   Next.js tự động chia bundle theo route. Dashboard chỉ load khi user
   truy cập, tránh load toàn bộ code từ đầu.

4. Serverless Functions:
   API routes trong Next.js chạy trên AWS Lambda (serverless).
   Tiết kiệm chi phí so với dedicated server.

--- Cấu hình Web App ---

Trong PythonAnywhere Web App config:

   /home/user/BI-Dashboard/backend/wsgi.py

2. Virtualenv:

3. Python version:

```python
import sys

# Add project directory to path

if path not in sys.path:
    sys.path.append(path)

# Set environment variables
os.environ['PYTHONUNBUFFERED'] = '1'

# Wrap with WSGI adapter
from fastapi.middleware.wsgi import WSGIMiddleware
```

3.4.4 Kết nối Frontend-Backend
================================================================================

Sau khi deploy cả Frontend và Backend, cập nhật CORS và URL:

1. Cập nhật Backend (backend/main.py):
   ```python
   app.add_middleware(
       CORSMiddleware,
       allow_origins=[
           "http://localhost:3000",              # dev
           "https://bi-dashboard-green.vercel.app",  # prod
       ],
       allow_credentials=True,
       allow_methods=["*"],
       allow_headers=["*"],
   )
   ```

2. Cập nhật Frontend (.env.production):
   NEXT_PUBLIC_API_BASE_URL=https://your-app.pythonanywhere.com

3. Rebuild & deploy Frontend:
   vercel --prod

4. Test kết nối:
   - Truy cập https://bi-dashboard-green.vercel.app/login
   - Đăng nhập → gửi request /auth/login tới Backend
   - Nhận JWT token → lưu localStorage
   - Tải Dashboard → gọi /sale-profit/api/dashboard/sales
   - Kiểm tra CORS headers không bị block

3.4.5 Tối ưu hóa Hiệu Năng
================================================================================

--- Caching Strategy ---

Backend tích hợp ba lớp cache:

1. In-Memory TTL Cache (10-15 phút):
   - Lưu kết quả tính toán KPI dưới dạng dict
   - Query cache hit: < 1ms response time
   - Tự động expire sau TTL

2. Parquet File Cache (đến khi ETL refresh):
   - Lưu toàn bộ DataFrame dưới dạng .parquet
   - 15-25x faster than MySQL query
   - Không chiếm RAM (disk-based)

3. Database Query Cache (replication):
   - MySQL query result cached ở Connection Pool
   - Giảm round-trip tới DB

--- Database Optimization ---

1. Indexes:
   ```sql
   CREATE INDEX idx_sales_date ON FactSales(DateKey);
   CREATE INDEX idx_sales_store ON FactSales(StoreKey);
   CREATE INDEX idx_sales_product ON FactSales(ProductKey);
   ```

2. Aggregate Tables (Pre-computation):
   - summary_daily_sales: chứa dữ liệu đã group-by
   - Thay vì scan triệu dòng, query chỉ scan hàng trăm
   - Giảm query time 100x

3. Connection Pooling:
   SQLAlchemy pool_size=5, max_overflow=10
   - Tối ưu cho 10-30 concurrent requests
   - Tránh connection leak

--- Frontend Optimization ---

1. Code Splitting:
   Next.js automatic per-route splitting
   - Page weight: ~150KB (base) + ~50KB (page)
   - Chart libraries lazy-loaded

2. Image Optimization:
   ```tsx
   <Image src="/chart.png" alt="..." width={800} height={600} />
   ```
   → Automatic compression, webp format

3. Static Generation (ISR):
   Homepage static, revalidate mỗi 600 giây
   → First contentful paint < 1 second

--- ETL Performance ---

1. Incremental Load (Watermark):
   - Full load: 90 giây (190K rows)
   - Incremental: 5 giây (50 rows mới)
   - Chạy mỗi 30 phút (không ảnh hưởng user)

2. Background Tasks:
   - ETL chạy daemon thread (không block API)
   - Cache refresh background
   - DW poller (realtime) mỗi 15 giây

3.4.7 Continuous Integration & Deployment (CI/CD)
================================================================================

--- GitHub Actions (Optional) ---

File: .github/workflows/deploy.yml

```yaml
name: Deploy

on:
  push:
    branches: [ main ]

jobs:
  deploy-frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - run: npm install && npm run build
      - run: npm run test
      - run: vercel --prod --token ${{ secrets.VERCEL_TOKEN }}

  deploy-backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - run: pip install -r backend/requirements.txt
      - run: python -m pytest backend/
      - run: |
          git push pythonanywhere main
          # Trigger PythonAnywhere reload
```

--- Deployment Checklist ---

□ Code review trước merge main
□ Chạy test suite locally
□ Update version number (package.json, setup.py)
□ Update CHANGELOG
□ Merge → auto-trigger CI/CD
□ Verify Frontend loads trên Vercel
□ Verify Backend health check trên PythonAnywhere
□ Smoke test: đăng nhập → load dashboard → check data
□ Monitor logs trong 30 phút đầu triển khai

3.4.8 Disaster Recovery & Backup
================================================================================

--- Database Backup ---

1. Manual Backup (Weekly):
   ```bash
   mysqldump -u user -p retails_dataset > backup_2026-04-12.sql
   ```

2. Automated Backup (Daily):
   - PythonAnywhere backup feature (nếu upgrade)
   - Hoặc crontab: 0 2 * * * mysqldump ... > /backup/db_$(date).sql

3. Disaster Recovery Time:
   - RTO (Recovery Time Objective): < 1 giờ
   - RPO (Recovery Point Objective): 1 ngày

--- Code Backup ---

1. Git Repository:
   GitHub (public/private) = authoritative source

2. Automated Backups:
   Vercel auto-backup từ Git
   PythonAnywhere Dropbox integration (nếu enable)

--- Handling Outages ---

1. Database Down:
   - Cache menjadi stale
   - Frontend vẫn load historical data từ Parquet
   - Điểm chết: realtime data unavailable (SSE fails)

2. Backend Down:
   - Frontend shows "Service Unavailable"
   - User redirected tới status page
   - Email alert tới admin

3. Frontend Down:
   - Static fallback page hosted on S3 (optional)
   - Users directed tới mirror site

3.4.9 Scaling Strategy
================================================================================

Nếu ứng dụng tăng trưởng người dùng:

--- Scale Vercel Frontend ---

1. Increase node size:
   Vercel Free → Pro (~$25/month)
   - Production deployment priority
   - Unlimited deployments
   - Team collaboration

2. Edge Middleware:
   Cache Responses ở Edge Locations
   - Lower latency globally
   - Reduce Backend load

--- Scale PythonAnywhere Backend ---

1. Upgrade to Paid Plan:
   Free (512MB) → Beginner (1GB) → Professional (2GB)
   → Dedicated server

2. Load Balancing:
   Deploy multiple Backend instances
   - nginx reverse proxy
   - Round-robin load balancing
   - Shared MySQL database

3. Database Scaling:
   - MySQL replication (read + write nodes)
   - Sharding by region (Asia, Europe, Americas)
   - Read-only replicas cho reporting

--- Caching Layer Scaling ---

1. Redis Cache (shared memory):
   - Replace in-memory dict with Redis
   - Multiple Backend instances share same cache
   - Publish-subscribe untuk invalidation

2. Parquet S3 Storage:
   - Move Parquet files từ local disk → AWS S3
   - Faster cloud sync, distributed caching

Hệ thống BI Dashboard đã được triển khai thành công lên các nền tảng đám

hạn chế.
